# Code signing policy

**Status: SplitNest's Windows releases are not code signed yet.** The project intends to apply to the
[SignPath Foundation](https://signpath.org) for free code signing for open-source projects. Until an
application is approved and this notice is updated, every SplitNest release is unsigned, and Windows
SmartScreen may warn about it (see [Download](https://splitnest.dev/download/)).

Once approved, Windows releases will carry this statement:

> Free code signing provided by [SignPath.io](https://about.signpath.io), certificate by [SignPath Foundation](https://signpath.org).

The publisher shown by Windows for signed files will then be **SignPath Foundation**.

## Team roles

SplitNest is maintained by one person. The roles SignPath Foundation requires are all held by the
repository owner:

| Role | Who | What it means |
|---|---|---|
| Committer (author) | [Souf CH (@chafian)](https://github.com/chafian) | May change the source code without further review. |
| Reviewer | [Souf CH (@chafian)](https://github.com/chafian) | Reviews and merges every contribution from anyone who is not a committer (pull requests). |
| Approver | [Souf CH (@chafian)](https://github.com/chafian) | Approves each signing request by hand, after checking that it comes from the release workflow for a tagged version. |

Two-factor authentication is enabled on the maintainer's GitHub account.

Requirements for everyone holding a role: multi-factor authentication on GitHub and on SignPath, and
no use of signing for anything other than this repository's own release builds. If the team grows,
this table and the repository's permission settings are updated together.

## What is signed, and what is not

Only binaries that this repository's release workflow builds for SplitNest are signed:

| File | What it is |
|---|---|
| `splitnest.exe` | The application. Built by Electron Forge from this repository: Electron's runtime with SplitNest's code, name, icon and version information. |
| `SplitNest-win32-x64-Setup.exe` | The Windows installer (Squirrel.Windows), generated by this repository's build. |
| `splitnest_ExecutionStub.exe` | Squirrel's launcher for SplitNest, generated by this repository's build (pending confirmation by SignPath Foundation that it may be signed). |

Files built by other open-source projects ("upstream") are shipped exactly as those projects publish
them and are **never signed with SplitNest's certificate**: Electron's libraries (for example
`ffmpeg.dll`, `vulkan-1.dll`), node-pty's native modules and winpty, Microsoft's ConPTY files
(`conpty.dll`, `OpenConsole.exe`, already signed by Microsoft) and Squirrel's `Update.exe`. Every
release lists every binary, marked *ours* or *upstream*, with its SHA-256 hash, version information and
signature status, generated by [`scripts/binary-inventory.mjs`](scripts/binary-inventory.mjs).

Every signed binary has product name **SplitNest**, company **SplitNest**, and the release's version as
product version. The release build checks this and fails if a file differs.

## How releases are built

- Releases are built only by GitHub Actions, on GitHub-hosted Windows runners, from a version tag
  (`vX.Y.Z`) in this public repository, with dependencies installed from the committed lockfile.
- The workflow runs the tests, builds the installer and the portable ZIP, and publishes them to
  [GitHub Releases](https://github.com/chafian/splitnest/releases) together with SHA-256 checksums.
  Build logs are public in the repository's Actions tab.
- Once signing is approved: the workflow submits the build output to SignPath, each request is
  approved by hand by the approver, and a release is only published when every expected file is
  signed and the checks pass. A release is never published partly signed.

## Privacy

See the [privacy policy](https://splitnest.dev/privacy/). In short: SplitNest has no telemetry or
analytics. Starting with version 0.2.0 it checks for updates (enabled by default, explained when the
app first starts, and can be turned off). That check contacts GitHub only (this repository's GitHub
Releases); GitHub's privacy terms are linked from the privacy policy.

## Verifying a download

- Compare the SHA-256 hash of your download with `SHA256SUMS.txt` from the same release
  (instructions on the [download page](https://splitnest.dev/download/#verify-the-sha-256-checksum)).
- For signed releases, check the signature in PowerShell:
  `Get-AuthenticodeSignature .\SplitNest-win32-x64-Setup.exe`.

## Reporting a problem

If you believe a SplitNest binary was signed improperly, or that a signed file is harmful, please
report it privately as described in [SECURITY.md](SECURITY.md), or open an issue for anything that
is not sensitive.
